# Web et UI

## Partir du parcours

Définir l'action prioritaire : comprendre l'offre, voir le planning, comparer, réserver, contacter ou trouver le lieu. Construire l'interface autour de cette action.

Pour une landing page Koutio, considérer selon le besoin :

- promesse claire ;
- différence entre Training et Vitalité ;
- activités et niveau attendu ;
- planning ou accès au planning ;
- tarifs et conditions ;
- preuve par le lieu, l'équipe ou la communauté ;
- accès, contact et réservation ;
- réponses aux objections principales.

## Utiliser un système cohérent

Créer ou réutiliser des tokens pour : couleurs validées, typographies, espacements, rayons, ombres et états interactifs. Ne pas coder une couleur approximative comme valeur officielle.

Réutiliser les composants existants avant d'en créer de nouveaux. Respecter les conventions du dépôt et limiter les dépendances supplémentaires.

## Concevoir mobile d'abord

- garder le message et l'action principale visibles rapidement ;
- éviter les titres gigantesques qui repoussent l'information utile ;
- rendre les horaires et tarifs scannables ;
- prévoir des cibles tactiles confortables ;
- tester les longs mots, accents et retours à la ligne en français ;
- ne pas cacher l'information essentielle dans un carrousel.

## Accessibilité et robustesse

- utiliser une structure sémantique ;
- maintenir un ordre de lecture logique ;
- fournir des libellés et textes alternatifs utiles ;
- assurer la navigation au clavier ;
- vérifier le contraste avec la norme officielle actuelle ;
- ne pas transmettre une information uniquement par le jaune ou le bleu ;
- respecter les préférences de réduction des animations ;
- tester les états vide, chargement, erreur et succès lorsqu'ils existent.

## Implémenter

Inspecter le code, le design system et les composants avant modification. Préserver l'architecture existante. Réaliser les tests pertinents et vérifier visuellement les principaux points de rupture.

Pour une nouvelle interface, fournir au minimum :

- structure des pages ;
- composants principaux ;
- tokens ;
- états responsive ;
- comportement des interactions ;
- critères d'acceptation vérifiables.

Ne pas confondre fidélité visuelle et qualité : signaler un design source qui dégrade clairement la lisibilité, l'accessibilité ou la conversion.
